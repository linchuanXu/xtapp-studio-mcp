## 一句话

插件是一个跑在你电脑上的 MCP 服务 `xtapp_studio`。它读**你电脑上的应用文件夹**，
推给 XTApp Studio 的预览页去跑，再替 AI 按键、点屏、截图。它不自己跑 Lua，也不会
把东西存到云上。云上那份只有你在 Studio 里点「保存」才会写。

## 各个 AI 工具怎么接

| 工具 | 方式 | 能多做什么 |
|---|---|---|
| Codex | 市场插件 | 同一份 MCP，外加两份 skill 和右侧预览状态面板 |
| Cursor | MCP | 用 Cursor 自带浏览器打开预览页 |
| WorkBuddy、Claude Code 等其他工具 | 通用 MCP | 没有面板；AI 把预览地址给你，你自己打开 |

通用 MCP 的接法都一样：在本仓库目录里运行

```bash
node scripts/cursor-mcp-config.mjs
```

把打印出来的 `mcpServers.xtapp_studio` 合进该工具的 MCP 配置（WorkBuddy 在它的 MCP
设置里添加一个本地 stdio 服务，命令 `node`，参数是打印出的
`mcp/server.bundle.mjs` 绝对路径），重载后新开一轮对话。需要 Node.js 18 以上。

本仓库对应哪个 Studio 地址，看根目录的 `region.json`。

## 做一次预览时发生了什么

```text
你的应用文件夹 ──插件读取──▶ 中转（临时，15 分钟不用就过期）──▶ Studio 预览页
                                                              │
                                              浏览器里的一份工程 ──▶ 模拟器
```

1. 插件读文件夹里的 `manifest.json`、`*.lua`、`data/` 和 `lang/` 下的文本、`assets/`
   和 `raw/` 下的图片。`docs/`、`tmp/`、`prototypes/`、`.tmp/` 不读。单个文本文件最大
   256KB，单张图最大 2MB。
2. 发给 Studio。第一次全量，之后只发改动。
3. Studio 预览页把它写进**浏览器里**的一份工程，然后在模拟器里跑。
4. 预览地址由 AI 给你，带一串会话号。请打开它并保持开着。出现登录页就自己登录，
   AI 不会也不该替你填密码。同一个会话开了两个标签页时，最后打开的那个生效。

同一个文件夹再次预览，会回到同一个预览页和同一份工程。

## 你的东西存在哪

| 在哪 | 是什么 | 会不会丢 |
|---|---|---|
| **你电脑上的应用文件夹** | 源码的正本。AI 改的就是这里 | 和普通文件一样。建议用 Git |
| 浏览器里的 Studio 工程 | 预览用的副本，加上你在 Studio 里上传或生成的图 | 清浏览器数据、换电脑就没了 |
| 云工作区（你的账号） | 你点「保存」时的那一份草稿 | 不会，换电脑登录就能打开 |
| 模拟器存储卡 `/AppFiles/<app_id>/` | 应用运行时自己存的数据，不是源码 | 跟着预览设备 |
| `~/.xtapp/` | 插件记住「哪个文件夹对应哪个预览会话」 | 删了只是开新会话 |

记住两件事：

- **预览同步不等于保存。** AI 每次预览只更新浏览器里的工程。想换电脑也能打开，
  在 Studio 顶栏点「保存」（要登录）。云上如果有更新的一份，Studio 会问你要不要覆盖，
  不会自动合并。
- **保存不等于发布。** 保存后的草稿只有你自己看得见。上架商店在账号后台。

## 文件夹对应 Studio 里哪个工程

Studio 按这个顺序找：

1. 文件夹里有 `docs/studio.cloud.json`，写着 `{"cloudProjectId": "…"}`：用这份云工程。
2. 上次就是这个文件夹：接着用。
3. 按 `manifest.json` 里的 `display_name` 找同名工程，或者你账号里**只有一份**同名草稿。
4. 都对不上：新建一份。

除了新建，Studio 在覆盖已有工程前都会问「允许本地插件同步到「…」？」。不是你想要的
那份就点取消。

**换一台电脑继续做：** 把应用文件夹带过去（比如用 Git）。账号里只有一份同名草稿时会
自动对上；有好几份时会新建，你在 Studio 保存时会让你选更新哪一份，那里能看到云工程
编号。想以后都稳稳对上，就把这个编号写进文件夹里的 `docs/studio.cloud.json`。这个文件
只在你电脑上起作用，不会进云上的草稿，也不会进商店包。

**想另开一份：** Studio 的项目管理里选「另存为新的云工程」。

**用文件夹整份覆盖一个已有工程：** 比如在另一个账号里改过，但商品绑在这边的工程上。告诉
AI「用这个文件夹覆盖 Studio 里的工程 <云工程编号>」。Studio 会先问你；同意后先存一份
「覆盖前快照」到历史，再用文件夹里的文件和图片整份替换，只在 Studio 里的图和文档也会删
掉。工程编号、`app_id` 和商品绑定不变，AI 随后把编号和 `app_id` 写回文件夹，以后照常同
步。点取消就什么都不改。

## 图片和文件：哪边说了算

| 情况 | 结果 |
|---|---|
| 文件夹里改了或加了文件、图片 | 下次预览推过去 |
| 文件夹里删了以前推过的文件、图片 | Studio 里也删掉 |
| 图片是在 Studio 里上传或生成的 | 预览时保留，AI 会告诉你一次 |
| 想把 Studio 里的图拿回文件夹 | 让 AI 拉回来（`pull_xtapp_studio_source`），图片存成 `assets/<名字>.xic`；文件夹里已有且不同的默认不覆盖 |
| 想删掉只在 Studio 里的图 | 告诉 AI 删哪张 |

PNG、JPG、WebP 推过去时会转成设备格式 XIC。

注意：你在 Studio 里直接改的代码不会自动回到文件夹。下次 AI 预览时，文件夹里的版本会
盖掉它。要留下，先让 AI 拉回来。

## 存储卡上的应用数据

应用用 `ctx.files` 存的东西在模拟器存储卡 `/AppFiles/<app_id>/`。AI 可以列出、读取、
写入、删除这里的文件，用来查看存档或准备测试数据。需要 `manifest.api` 2.9 以上，
`manifest.json` 里有 `app_id`，并且预览页正在显示这个工程。

## 插件过旧

Studio 发现插件比最新版旧，会弹「XTApp 插件需要更新」。对 AI 说「升级 XTApp 插件」：

- Codex：AI 会走 Codex 市场升级。升级后**新开**一个任务。
- 其他工具：在本仓库目录 `git pull`，重载 MCP，新开对话。

## 常见问题

| 现象 | 怎么办 |
|---|---|
| 预览页是登录页 | 自己登录，再回到同一个预览地址 |
| AI 说 `not_connected` | 预览页没开或关掉了，重新打开 AI 给的地址 |
| 同步到了别的工程 | 在确认框点取消；或在 `docs/studio.cloud.json` 写上要用的编号 |
| 换电脑后工程是空的 | 之前没在 Studio 点过保存。文件夹还在就重新预览，然后保存 |
| 只有 Codex 有右侧面板 | 正常，其他工具没有 |
| 存储卡相关操作报错 | 检查 `manifest.api` ≥ 2.9、有 `app_id`、预览页显示的是这个工程 |
